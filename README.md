# Poker Online

Простой онлайн-покерный стол для небольших компаний. Проект собирается в один Docker-контейнер и деплоится на Render.

## Архитектура

- В памяти хранится состояние стола (`TableService`, `ConcurrentHashMap`), а не истории игр.
- PostgreSQL/Neon используется только для сохранения истории раздач через Flyway и JPA.
- Реальный обмен идёт через STOMP (`/topic/table`, `/topic/chat`, `/user/queue/private`).

## Требования

- Java 21
- Maven 3.9+
- Docker
- PostgreSQL / Neon account

## Переменные окружения

Создайте `.env` на основе `.env.example`:

```bash
cp .env.example .env
```

Пример:

```bash
export PORT=8080
export DATABASE_URL="jdbc:postgresql://host.neon.tech:5432/neondb?sslmode=require"
export DATABASE_USERNAME="your_user"
export DATABASE_PASSWORD="your_password"
```

## Запуск локально

```bash
mvn clean package -DskipTests
java -jar target/poker-online-1.0.0.jar
```

Открыть: http://localhost:8080

## Docker

```bash
docker build -t poker-online .
docker run --rm -p 8080:8080 --env-file .env poker-online
```

## Деплой на Render

1. Создайте аккаунт на Render.
2. Нажмите New -> Web Service.
3. Подключите GitHub репозиторий проекта.
4. Выберите Docker как тип сборки.
5. Укажите порт `8080`.
6. Добавьте env-переменные:
   - `DATABASE_URL`
   - `DATABASE_USERNAME`
   - `DATABASE_PASSWORD`
   - `PORT=8080`
7. Включите автодеплой и запустите сервис.
8. WebSocket работает по `wss://` в продакшене, для клиента используйте `new SockJS('/ws')`, а хост задайте через `window.location.origin`.

## Neon PostgreSQL

1. Создайте БД на Neon.
2. Скопируйте connection string.
3. Добавьте `?sslmode=require` в JDBC URL.
4. Укажите `DATABASE_URL` / `SPRING_DATASOURCE_URL` в Render env.

## Игровая логика

- Для старта нужны минимум два игрока с фишками; кнопку может нажать любой сидящий за столом.
- Один браузер занимает только одно место: идентификатор хранится в `localStorage`, повторный вход в той же браузерной сессии использует то же место. Без авторизации нельзя надёжно ограничить одного человека на разных устройствах или в разных браузерах.
- Карманные карты отправляются игроку приватно; общая рассылка стола их не содержит. Карты оставшихся игроков открываются только на showdown.
- Раздача идёт из перемешанной 52-карточной колоды; перед каждой улицей сжигается карта.
- Dealer / small blind / big blind перемещаются к следующим занятым местам; в heads-up дилер ставит small blind.
- Стадии: Preflop → Flop → Turn → River → Showdown
- Доступные действия зависят от очереди и текущей ставки. Call автоматически уравнивает ставку; Bet / Raise задают целевую общую ставку игрока на текущей улице.
- Блайнды, коллы, ставки и олл-ины учитываются в общем банке; побочные банки распределяются только между игроками, внесшими соответствующий вклад и не сбросившими карты.
- Победитель и ничья определяются по лучшей пяти-карточной комбинации. После 30 секунд без действия игрок автоматически check, если может, иначе fold.
- Игрок с нулевым стеком остаётся за столом зрителем и пропускает следующие раздачи; остальные продолжают, пока у нескольких игроков есть фишки.
- Если выбывший игрок переподключится тем же профилем браузера до сброса матча, он вернётся с нулевым стеком, а не получит повторный стек.
- Когда фишки остаются только у одного игрока, матч заканчивается. Кнопка «Сбросить матч» доступна между раздачами: с подтверждением она выдаёт каждому игроку за столом начальный стек в 1 000 фишек и начинает новый матч. Во время раздачи сброс заблокирован.
- Уход игрока во время раздачи автоматически сбрасывает его карты; место освобождается для следующей раздачи.
- Интерфейс поддерживает русский и английский языки; выбор сохраняется в браузере.

## Примечания

- Состояние игрового стола хранится в памяти для максимальной скорости и простоты масштабирования на небольшую комнату.
- История раздач сохраняется в PostgreSQL только для статистики.
- Никаких секретов и паролей в репозитории: только env-переменные и `.env.example`.
